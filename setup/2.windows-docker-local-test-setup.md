# Windows Docker Local Test Setup

This guide installs and configures Docker on **Windows OS** for a small local testing stack.

Target setup:

```text
Windows OS
  ↓
Docker Desktop
  ↓
WSL2 backend
  ↓
Linux containers
  ↓
Floci + PostgreSQL + Redis + optional OpenSearch
```

Use **Linux containers** for this stack. Do not use Windows containers unless you specifically need native Windows container workloads.

---

## 1. What You Will Install

You need:

1. Windows 10/11
2. WSL2
3. Ubuntu or another Linux distro through WSL
4. Docker Desktop for Windows
5. Docker Desktop configured to use WSL2 backend
6. Docker running in Linux container mode

---

## 2. Check CPU Virtualization

Docker Desktop with WSL2 requires virtualization support.

### Check in Task Manager

1. Press `Ctrl + Shift + Esc`
2. Go to **Performance**
3. Click **CPU**
4. Check this line:

```text
Virtualization: Enabled
```

If it says `Disabled`, enable virtualization from BIOS/UEFI.

Common BIOS names:

```text
Intel VT-x
Intel Virtualization Technology
AMD-V
SVM Mode
```

---

## 3. Install WSL2

Open **PowerShell as Administrator**.

Run:

```powershell
wsl --install
```

This installs WSL and usually installs Ubuntu as the default Linux distribution.

Restart Windows after installation if prompted.

---

## 4. Confirm WSL Version

After restart, open PowerShell and run:

```powershell
wsl -l -v
```

Expected output should show version `2`:

```text
  NAME      STATE           VERSION
* Ubuntu    Running         2
```

If Ubuntu is version `1`, convert it to WSL2:

```powershell
wsl --set-version Ubuntu 2
```

Set WSL2 as the default for future distros:

```powershell
wsl --set-default-version 2
```

---

## 5. Update WSL

Run:

```powershell
wsl --update
```

Then shut down WSL once:

```powershell
wsl --shutdown
```

---

## 6. Install Docker Desktop

Download and install Docker Desktop for Windows:

```text
https://www.docker.com/products/docker-desktop/
```

During installation, keep this option enabled:

```text
Use WSL 2 instead of Hyper-V
```

After installation, restart Windows if prompted.

---

## 7. Enable Docker WSL2 Backend

Open Docker Desktop.

Go to:

```text
Settings → General
```

Enable:

```text
Use the WSL 2 based engine
```

Click:

```text
Apply & Restart
```

---

## 8. Enable WSL Integration

Open Docker Desktop.

Go to:

```text
Settings → Resources → WSL Integration
```

Enable integration for your Linux distro, for example:

```text
Ubuntu
```

Click:

```text
Apply & Restart
```

---

## 9. Confirm Linux Container Mode

Docker Desktop should use Linux containers by default.

To confirm:

1. Look for the Docker whale icon in the Windows system tray.
2. Right-click it.
3. If you see:

```text
Switch to Windows containers
```

then you are already using **Linux containers**.

If you see:

```text
Switch to Linux containers
```

click it to switch to Linux containers.

---

## 10. Verify Docker Installation

Open PowerShell and run:

```powershell
docker version
```

Then run:

```powershell
docker info
```

Check that Docker is running.

Now test a small Linux container:

```powershell
docker run --rm hello-world
```

You should see a success message from Docker.

Optional small Alpine test:

```powershell
docker run --rm alpine:latest echo "Linux containers are working"
```

Expected output:

```text
Linux containers are working
```

---

## 11. Create Local Docker Compose File

In your project root, create:

```text
docker-compose.yml
```

Add:

```yaml
name: local-test-stack

services:
  floci:
    image: floci/floci:latest
    container_name: local-floci
    ports:
      - "4566:4566"

  postgres:
    image: postgres:17-alpine
    container_name: local-postgres
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: app
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data

  redis:
    image: redis:7-alpine
    container_name: local-redis
    ports:
      - "6379:6379"
    command: ["redis-server", "--save", "", "--appendonly", "no"]

  # Optional: only start when you need search
  opensearch:
    image: opensearchproject/opensearch:latest
    container_name: local-opensearch
    profiles:
      - search
    environment:
      - discovery.type=single-node
      - DISABLE_SECURITY_PLUGIN=true
      - OPENSEARCH_JAVA_OPTS=-Xms512m -Xmx512m
    ports:
      - "9200:9200"
      - "9600:9600"
    volumes:
      - osdata:/usr/share/opensearch/data

volumes:
  pgdata:
  osdata:
```

---

## 12. Create `.env`

Use this when your Node.js app runs directly on Windows:

```env
# Floci local AWS emulator
AWS_ENDPOINT_URL=http://localhost:4566
AWS_REGION=us-east-1
AWS_ACCESS_KEY_ID=test
AWS_SECRET_ACCESS_KEY=test

# Local infra
DATABASE_URL=postgres://postgres:postgres@localhost:5432/app
REDIS_URL=redis://localhost:6379
OPENSEARCH_URL=http://localhost:9200

# App
LOG_LEVEL=info
NODE_ENV=development
```

---

## 13. Start Small Core Services

Run:

```powershell
docker compose up -d floci postgres redis
```

This starts:

```text
Floci      → http://localhost:4566
Postgres   → localhost:5432
Redis      → localhost:6379
```

---

## 14. Start OpenSearch Only When Needed

OpenSearch is heavy. Do not start it unless your feature needs search.

Run:

```powershell
docker compose --profile search up -d
```

If OpenSearch fails with memory map errors on Windows/WSL, run:

```powershell
wsl -d docker-desktop
sysctl -w vm.max_map_count=262144
exit
```

Then retry:

```powershell
docker compose --profile search up -d
```

---

## 15. Check Running Containers

```powershell
docker ps
```

Expected core containers:

```text
local-floci
local-postgres
local-redis
```

If OpenSearch is enabled:

```text
local-opensearch
```

---

## 16. Test PostgreSQL

```powershell
docker exec -it local-postgres psql -U postgres -d app
```

Inside PostgreSQL:

```sql
SELECT 1;
```

Exit:

```sql
\q
```

---

## 17. Test Redis

```powershell
docker exec -it local-redis redis-cli ping
```

Expected output:

```text
PONG
```

---

## 18. Test Floci

Basic endpoint check:

```powershell
curl http://localhost:4566
```

For AWS SDK clients, use:

```env
AWS_ENDPOINT_URL=http://localhost:4566
AWS_REGION=us-east-1
AWS_ACCESS_KEY_ID=test
AWS_SECRET_ACCESS_KEY=test
```

---

## 19. If Node.js Also Runs Inside Docker

If your Node.js app runs inside Docker Compose, use service names instead of `localhost`.

Use:

```env
AWS_ENDPOINT_URL=http://floci:4566
DATABASE_URL=postgres://postgres:postgres@postgres:5432/app
REDIS_URL=redis://redis:6379
OPENSEARCH_URL=http://opensearch:9200
```

Reason:

```text
localhost from Windows       = your Windows machine
localhost from a container   = that same container
postgres / redis / floci     = Docker Compose service names
```

---

## 20. Stop Services

Stop containers but keep data:

```powershell
docker compose down
```

Stop containers and delete local volumes/data:

```powershell
docker compose down -v
```

Use `-v` only when you want to reset local PostgreSQL/OpenSearch data.

---

## 21. Common Windows Troubleshooting

### Docker says WSL is not installed

Run:

```powershell
wsl --install
wsl --update
wsl --shutdown
```

Then restart Docker Desktop.

---

### Docker command not found

Close and reopen PowerShell.

If still not working, restart Windows.

---

### Docker Desktop stuck starting

Try:

```powershell
wsl --shutdown
```

Then reopen Docker Desktop.

---

### Container ports already in use

Check which process is using the port:

```powershell
netstat -ano | findstr :5432
netstat -ano | findstr :6379
netstat -ano | findstr :4566
netstat -ano | findstr :9200
```

Then stop the conflicting process or change the port in `docker-compose.yml`.

---

### OpenSearch fails on Windows

Run:

```powershell
wsl -d docker-desktop
sysctl -w vm.max_map_count=262144
exit
```

Then:

```powershell
docker compose --profile search up -d
```

---

## 22. Best Daily Commands

Start core local stack:

```powershell
docker compose up -d floci postgres redis
```

Start with OpenSearch:

```powershell
docker compose --profile search up -d
```

Stop stack:

```powershell
docker compose down
```

Reset stack data:

```powershell
docker compose down -v
```
